# Defined line-segment background editing

- **Status:** Accepted
- **Date:** 2026-10-17
- **Implementation:** Partially implemented; native and manual source paths require compilation and behavioral qualification.
- **Priority:** High

## Context

The ordinary Experiment background UI in [ADR-0017](0017-app-gui-design.md) and `BackgroundListModel` already exposes line-segment position, intensity, free flags, IDs, Add and Remove. Its old Add chooses a default position immediately; the assistant needs an explicit scientifically justified anchor through that same visible UI. Position/removal previously used closed scalar/collection Edits without structural Undo. [ADR-0020](0020-calculation-worker-and-publication.md) owns the single closed Edit, LivePreview, calculation publication and Undo boundary. [ADR-0037](0037-assistant-controller-and-tools.md) owns original native calls, once-only outcomes, real widget input, resource admission and currentness. Background ID renaming already follows aliases and fit-result names through the model's existing rename rule.

## Decision

A typed `BackgroundPointInput` names add/update/remove, exact anchor ID and explicit position/intensity/free values where applicable. One preparation borrows the actual owned line-segment bank, applies the original caller policy and relation ownership, and preowns the before/after shared-row lists. Native requests require measured data, a matching complete axis/observation shape and finite distinct sorted in-domain anchors. Ordinary manual Add/position/remove retains simulation/calculation-only and no-measurement sources, finite extrapolation, duplicate positions and original row order; no measured-axis traversal or observation-length condition is imposed on that caller. Only a changed/new row is copied; surviving rows retain their actual objects, parameter specs, values, uncertainties and flags. Unchanged intensity preserves uncertainty; changed intensity uses the existing parameter setter. Removing an alias target refuses. Dependent intensity/free changes refuse. No observation, sigma, exclusion, weight, composition, unrelated parameter or relation is edited.

A closed background Edit rechecks optional source presence/identity, calculation-only state, raw-column writes where data exists, mode, exact row membership and relation lineage immediately before the single `ItemVec::assign` commit. The retained preparation keeps its original native/manual source policy. New native results retain strict measured/domain checks; Undo restores the exact lawful captured original arrangement rather than admitting it as a new native request. A native removal/update may therefore repair an ordinary duplicate or extrapolating anchor, and its one inverse still restores that original finite arrangement and order. That existing collection admits new columns, holds and anchors before live mutation. Its adjacent committed latch precedes publication. One preowned structural Undo restores only the exact prior shared rows, with surviving unrelated row objects shared rather than overwritten. A replaced source/owner, changed affected-row state or conflicting relation lineage refuses Undo. Restoration for either caller preserves the captured finite extrapolating/equal-position arrangement and original order; it does not silently clamp, sort or normalize the user's anchors. Exact live membership, affected-row snapshots and source/dependency conflicts remain authoritative; surviving unrelated rows retain their actual later state. It never restores a whole project. Renaming uses the existing common alias/correlation rename rule and records the prior IDs for ordinary Undo.

Ordinary Add opens an inline staged form in Experiment/Main. Operation, exact ID, position, intensity and refine flag are normal manual controls. Only Apply invokes the common typed editor. Invalid numeric text or an obsolete original bank refuses while preserving the draft; blur does not commit. Existing row position/removal use the same preparation and Undo, and intensity/free controls keep their existing parameter editor. A genuine assistant takeover transfers the original view draft without changing event target geometry. Non-takeover cleanup removes only the exact original stage, with a loading/identity fence against synchronous replacement while form properties notify.

The app's `edit_background` tool uses that common editor directly in normal mode. In Show actions it clicks the genuine Experiment/Main controls only when needed, expands/reveals the owning group with existing real header/wheel input, chooses/types the actual form fields and clicks its real final Apply. A prearmed exact typed receipt binds the form output to the original native call. Current account, original RPC, owner, work/source stamps, deadline, Stop, manual drafts and genuine takeover stay authoritative. Cleanup balances the original helper before terminal external QML cleanup and cannot cancel a newer input. Applied/published/uncertain outcomes retain the actual Edit and Undo; asynchronous calculation is not a completed fit.

Native requests retain the existing inclusive 256-row and 256 UTF-8-byte identity policy, plus bounded borrowed source/alias work and a separately admitted temporary preparation envelope. That envelope includes before/after/candidate pointers, selected-row copies, actual column/row/anchor/index roles and ordinary model publication. Existing context/response/transport roles remain separate; no cap is raised. Ordinary manual row position/remove/rename does not acquire the assistant's 256-row ceiling. Both callers share science and Undo while native packet capacity is explicitly caller-owned. The staged manual form uses valid control-free Unicode; legacy row ID editing retains its prior common key rule. Ordinary row position/removal constructs the typed operation from the exact already-owned stored key bytes, without QString decoding/re-encoding or readmission through the new-text validator. A valid existing tab/control-containing key therefore remains movable/removable and Undoable. This is ownership of an existing row, not relaxed admission for a new native request.

The existing context and `inspect_project` metadata gain complete actual `background.anchors` descriptors: ID, position, intensity, uncertainty, free and dependence. The same borrowed encoded-size preflight accounts for every descriptor before the ordinary JSON writer constructs it. Oversized/nonfinite complete context refuses instead of truncating or inventing ordinal IDs. The native registry gains the implemented app operation; strict core bundled-skill prerequisites remain unchanged so app-only capability discovery cannot break bootstrap. Bundled instructions name the operation conditionally and preserve current-project refinement and access-scope rules.

## Consequences

A justified single anchor operation has the same validation/Undo behavior in ordinary manual, native normal and real visible paths. Polynomial/Chebyshev conversion, automatic background estimation, bulk operations, arbitrary input-folder access and visible Save are not provided by this operation. Existing source/root grants and actual native lifecycle remain unchanged. This source change requires ordinary compiled consumers and independent scientific, Undo, input, cancellation and reentry checks before delivery claims.

## Alternatives

Directly appending a guessed default and then editing it would expose an intermediate scientific state. A private assistant-only mutation decorated with pointer movement would not be a real GUI workflow. A full-project Undo would overwrite unrelated edits. Those alternatives are rejected in favor of the existing closed model Edit and first-class ordinary form.
