# Architecture Decision Records

edi's binding architectural decisions. ADRs **constrain implementation** and must exist before the
code they govern; they are part of the book. Each is `NNNN-slug.md` with the header block
(Status · Date · Implementation · Priority) followed by Context · Decision · Consequences ·
Alternatives (see [`template.md`](template.md)).

This page is the **single source of truth** for ADR status. **Whenever an ADR is added, amended,
implemented, or has its priority reassessed, update its row here** (and its in-page header block)
in the same change — see `AGENTS.md` §ADRs.

## Legend

- **Status** (the decision's standing): **Accepted** · **Proposed** · **Superseded** · **Deprecated**.
- **Impl** (how much is built): ✅ implemented · 🟡 partially implemented · ⬜ not implemented.
- **Priority** (near-term importance/urgency): **Highest** · **High** · **Medium** · **Low** · **Lowest**.
- **(shared)** marks a cross-cutting decision kept in sync with crysta via the Copier agent-OS
  template (ADR-0004) — edit it as a shared file, not an edi-only fork.
