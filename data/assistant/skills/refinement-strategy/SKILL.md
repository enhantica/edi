# Adaptive refinement of an actual Edi project

Version: 1.2.14. Scientific guidance for the available Edi APIs and official runtime, not an implemented autonomous controller or a format converter.

## Establish scope and evidence

For an authorized request to create/refine and decide the remaining details, state the bounded plan and proceed within the disclosed working copy and actual runtime permissions. Do not ask again solely because the next free group changes. Ask about missing experiment metadata, ambiguous associations, new chemical assumptions or an expanded objective. Respect actual consent, approval and Stop controls.

Inspect actual native measurement counts/weighting metadata, exclusions, phase links, instrument/profile convention, independent variables and existing relations through the offered typed summaries. Raw measurement arrays and plots stay local in the dedicated runtime; never invent an inspection unavailable through the original native controls/operations. Preserve this comparison population and objective across candidates. Record the actual native starting baseline and its reported fit status/metrics before comparing refinements; if no baseline is available, say so rather than invent one or substitute a number from another program. A file extension does not establish an experiment recipe. Never improve a reported residual by changing observations, uncertainty or exclusions without a separately justified and authorized change.

## Initial measured background

When choosing a NEW measured line-segment background rather than following user-supplied anchors, start with three distinct finite anchor positions spanning the actual measured range, with explicit justified starting intensities and free flags. Preserve explicit user anchors/values, supplied observations and exclusions. Obtain the actual range/basis from available approved evidence or ask one focused missing-input question; never invent a measured value or describe factory defaults as measurements. This three-point starting strategy is not a claim of scientific adequacy and does not change the valid minimum of two native/manual anchors. State the starting-intensity rationale and which intensities will be refined. Compound create_cwl_project.recipe.background is a direct array of exact position/intensity rows, fixed implicitly: no free/id fields or anchors wrapper. Delegated standalone edit_background add/update instead supplies explicit free=false during setup; retain desired final source flags separately for later authorized grouped Analysis. Use the actual measured-axis units and domain. Do not silently insert, redistribute or delete an existing/user-specified background to meet this strategy. There is no new estimator, material constant, automatic background operation or extra approval.

## Stage, compare and retain

Before any fit in either mode, follow project-assistance: complete Structure cell, each full Atom sites row including mapped chemical occupancy before the next, then ALL ADPs separately; finish ALL requested Structure members before any Experiment, then ALL requested Experiment members in actual interface-group order before Analysis. Keep imported background anchors initially fixed and apply retained final source flags in grouped Analysis after setup. Inspect actual free flags, relations and settled calculation; a refused prerequisite is not fulfilled. Explicit user scope and incoming operation operands remain authoritative. Release ONE justified Analysis category group, perform its actual fit, then inspect status/adopted/converged facts, comparable objective and physical validity BEFORE selecting the next group; preserve good stages. For ordinary sample-cell refinement retain a supplied known wavelength fixed: freeing it with an unanchored uniform cell dilation cannot determine absolute scale. Genuine wavelength calibration instead needs a known cell or other supported anchor; joint problems need their actual connected-group anchors. Preserve explicit user constraints and resolve genuine conflicts rather than silently fixing/freeing flags. Scientific staging is separate from GUI fill order. Assess peak-position agreement before accepting a scale-only fit. If displaced peaks make an adopted scale collapse, inspect and use eligible ordinary fit Undo or another actually supported restoration of credible scale before further local position refinement; do not impose scale then lattice then zero as an unconditional sequence. Retain justified earlier free variables while adding an identifiable alignment group; large mismatch needs a supported alignment/calibration start rather than blind all-free fitting. For CW keep the supplied known wavelength fixed and use only justified cell/two-theta corrections; a correct zero need not be numerically zero. Valid existing calibration/alignment can already satisfy this condition; do not force a known zero, absent group or symmetry-dependent coordinate free. Then choose profile/background and structural groups from actual misfit, scattering information and identifiability; releasing correlated groups does not prove they are determined.

Use a finite budget: a ceiling of 5–10 adaptive group passes is an owner-selected exploration budget, not a convergence criterion. Stop earlier on stable lack of useful improvement, unreliable steps, physical invalidity, cancellation or exhausted resources. Cycle correlated groups when useful, warming from the last accepted state; do not blindly repeat every group. Compare actual result status, convergence, residual, parameter movement, uncertainty and physical plausibility. MAX_ITER/NO_STEP are not convergence; failed/cancelled/unavailable/superseded fits do not authorize the next stage merely because some metrics look good.

For an actual adopted undesired fit, use offered `undo_fit` only while the actual `native_state.fit_undo_available` is true; the ordinary app action rechecks that this is still the most recent adopted fit and latest eligible history. Inspect restored owner, values, free flags, observations, weights, exclusions and relations before choosing another group. Never undo earlier science merely because a fit refused without adoption. If outcomes are partial/uncertain, inspect instead of replaying. If suitable restore is unavailable, report the recovery limit and do not claim rollback or continue candidates from an unrestored rejected state. A fit's pre-fit Undo is not a multi-path checkpoint stack. Separate saved checkpoints for alternative paths require actually offered operations and actual creation/restore evidence; do not promise an unavailable accepted-best controller. Retain failed candidates only as explicitly labelled diagnostics.

Reduced chi-square depends on the fitted observation population and the independent-variable degrees of freedom, not only residual size. Keep observations, weights, exclusions and objective comparable, and report available fitted-point/free-variable or degrees-of-freedom facts when interpreting a change. A different released variable set can change that denominator; a reduced chi-square value alone does not establish improvement. Across engines, establish matching model, profile, units, weighting, fitted population and residual definitions before comparing numbers; otherwise qualify the comparison, without inventing a missing reference residual or claiming numerical/scientific equivalence.

Holding another group fixed makes a group's uncertainty conditional. When identifiable and supported, finish with a simultaneous fit/covariance of the accepted independent variables. Report unresolved correlation, fixed-variable reasons and conditional uncertainties honestly; alternating groups alone does not establish independence.

## Select a strategy from the evidence

Use the selection criteria below directly; they do not require access to a private repository. If actually accessible, the physics knowledge book's **Refinement strategy selection** companion to chapter 8 supplies the detailed literature, alternatives and limits (Young 1993, chapter 1 §1.7; McCusker et al. 1999, §§5 and 7). Choose and briefly justify a path from the actual starting model, calibrated geometry, residual pattern and information content; adapt after each accepted stage:

- With a credible complete model, use staged **cumulative release**: retain justified earlier variables while admitting the next identifiable group. Early alignment precedes detailed width/asymmetry and structural fitting.
- When divergence, unreasonable shifts or correlation appear, reduce to a justified smaller variable set and diagnose before re-expanding. **Block cycling** temporarily fixes other groups; it is a conditional fit, not the same as cumulative release or proof of independence. Preserve useful earlier stages and finish with jointly assessed accepted variables when identifiable.
- If the structural model is incomplete, literature structure-free Le Bail/Pawley initialization may be appropriate. These are not offered Edi actions here; report that capability limit rather than imitate them by changing occupancies or inventing a parser/solver.
- For weakly determined structure, preserve established chemical constraints and use only actually offered relations. An affine equality is not a weighted geometric restraint or rigid-body model. Combined compatible datasets can add complementary information only with actual associations, calibration and supported shared variables; do not invent a joint experiment.
- Plausible alternative starts/models need an actual restorable starting state and authorized differing assumptions. Ordinary fit Undo is not a checkpoint bank or global-minimum guarantee. Stop and report an unavailable trial/restore path.

Do not copy an X-ray heavier-atoms-first heuristic into a universal neutron rule: choose sites/terms by actual scattering, symmetry and data support. Preserve explicit occupancies/composition and skip absent/dependent groups. The book's CW turn-on table is illustrative; it does not override calibration, data type or explicit scope. Detailed physics and source/page provenance stay in physics; current Edi schemas/options decide which parts can actually be executed.

## ADPs and mixed sites

Start with an appropriate simpler ADP model. Consider anisotropic ADPs only when site symmetry, resolution, overlap, statistics and systematic-error assessment support the extra independent variables. Use the actual tensor basis and physical positive-semidefinite assessment, uncertainty/covariance and stability. A lower residual or a large raw point count alone is insufficient. If the supported API cannot express the required constraints, report that limitation rather than manufacture an equivalent model.

Before fitting, establish whether different species genuinely co-occupy the same crystallographic site within one phase, and retain the user's intended shared-coordinate/ADP model. For a confirmed mixed site, express the supported shared coordinates/ADPs before refinement, or report the precise API/symmetry obstacle; merely noting the issue is insufficient. Treat occupancy sums/composition separately and preserve known fixed fractions such as 0.5/0.5. Accidental coordinate equality or different phases do not establish a shared site. Confirm allowed independent ADP terms and the actual tensor basis; never tie unrelated parameters or change chemistry silently.

When independently refined, confirmed same-phase co-occupied-site ADPs remain unresolved or have large uncertainty, an authorized delegated refinement suffices to run at least one bounded, physically supported shared-ADP candidate trial from the retained checkpoint. Do not request an additional shared-model preference or routine approval. An explicit user no-sharing/independent-ADP constraint prevails; report that limit rather than override it, and ask only about a genuinely new chemical assumption or scope conflict. Compare the same observations/weights/exclusions and objective, actual status/convergence/improvement, physical validity, stability and jointly assessed covariance. A low residual alone does not select the model; fixing a correlated group does not prove independence. Restore the accepted complete checkpoint if the candidate is rejected. Do not turn every high uncertainty into an equality constraint.

When offered, native `add_relations` supplies an explicit affine alias/constraint batch through the existing SDK validator, live editor and Undo; inspect actual parameter paths and existing relations first. Preserve manual relations and known fixed fractions. That mechanism alone does not implement checkpointed or isolated accepted-best trials: report a missing trial/restore operation rather than using Python or fabricating a successful shared-model comparison. Development API references do not grant a production capability.

## Use real operations

Use the actually offered native `inspect_project`, `list_parameters`, `diagnostics`, `set_parameters`, `set_free` and `run_fit`. They operate on the displayed C++ project. Native edits trigger asynchronous calculation; fit completion is the actual final native report, not a busy flag. No Python runtime/module/source checkout is required or permitted as a production fallback. A live fit can publish partial adopted values and does not implement isolated accepted-best trials. Preserve actual status and use only actually offered ordinary Stop/Undo operations; do not invent an Undo action or promise an unavailable checkpoint/restore/constraint/report operation.

Report the accepted artifact, actual operations/outcomes, rejected alternatives, independent/fixed variables, uncertainty qualifications and unsupported steps. A saved project or converged solver status alone does not prove a scientifically adequate refinement.
